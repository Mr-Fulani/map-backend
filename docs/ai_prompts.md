# AI-промпты и оценка качества

## Где применяются промпты

- Поиск изображений использует детерминированный `Search Query v3`, а не LLM.
- Генерация описаний выбирает активный `AIPromptTemplate` по задаче, домену
  каталога и маркетплейсу. При отсутствии записи используется безопасный шаблон из кода.
- Генеративная обработка медиа получает контролируемый сервером prompt; пользователь
  выбирает только разрешённый стиль фона.

## Версии и откат

Существующую версию промпта не следует редактировать. В админке создаётся новая запись
с увеличенным `version`, после чего действие «Активировать выбранную версию промпта»
атомарно отключает предыдущую версию того же scope. Каждый `AIRequestLog` сохраняет
ссылку на шаблон, version и SHA-256 фактического system prompt.

Scope разрешается в порядке:

1. точный домен + маркетплейс;
2. точный домен + любой маркетплейс;
3. любой домен + точный маркетплейс;
4. глобальный шаблон.

## Безопасность и повторные попытки

Данные товара передаются JSON-конвертом и объявлены недоверенными данными. Команды из
названий или описаний 1С не должны интерпретироваться как инструкции. Если валидатор
отклоняет результат, следующая попытка получает конкретную причину ошибки. Для OpenAI
Responses API дополнительно передаётся JSON Schema; остальные адаптеры продолжают
работать через единый JSON-контракт и серверный валидатор.

Подтверждённая применяемость передаётся структурированным массивом `trusted_fitments`:
марка, модель, поколение, годы, модификация, код двигателя и мощность. Дополнительный
`fitment_presentation` определяет безопасное представление для покупателя: короткий
список выводится точно, а большой сворачивается до подтверждённых марок и классов
автомобилей с количеством вариантов. Полный набор остаётся в структурированных данных.
Сервер проверяет, что компактное описание не потеряло марки и классы, а подробное —
конкретные автомобили.

Каталожные номера передаются отдельно в `catalog_number_presentation`. Форматные дубли
одного номера (например Mercedes-Benz с префиксом `A` и без него) скрываются только в
покупательском тексте, но исходные варианты сохраняются для поиска и интеграций. В
описании используется понятный заголовок «Номера для поиска и проверки совместимости».

Для Avito генератор соблюдает диапазон заголовка 50–200 символов и предел описания
7500 символов; целевая длина зависит от профиля полноты ниже. Адаптер фида повторно
применяет предельные значения перед созданием XML, включая старые и вручную изменённые
листинги.

Начиная с auto-parts prompt v6 сервер передаёт `content_profile`:

- `sparse` — есть только базовые данные: короткое честное описание без пустых разделов;
- `standard` — доступен один или несколько типов enrichment-данных: только релевантные
  разделы и факты;
- `rich` — не менее восьми подтверждённых записей в трёх и более группах: полноценная
  карточка с совместимостью, характеристиками, номерами и состоянием.

Для `rich` сервер отклоняет описание короче 350 символов, потерю артикула или доступных
разделов. На всех уровнях отклоняются шаблонные фразы вроде «предназначено для замены
изношенной детали»: повторная попытка получает причину и должна использовать факты.

Prompt v7 получает характеристики через buyer-facing нормализатор. Он скрывает EAN из
рекламного текста, объединяет одинаковые WVA/торговые номера и исправляет известные
ошибки перевода каталогов (`brake caliper bolts` → «болты тормозного суппорта»). В UI
EAN сохраняется, а нормализованные характеристики отображаются без смысловых дублей.
Валидатор также отклоняет внутренние формулировки «N записей/подтверждений», конструкцию
`VIN/номер` и повторение одного WVA-кода в нескольких частях описания.

Ручное подтверждение применяемости обучает глобальный граф знаний по связке
`бренд + артикул`. После этого подтверждённые автомобили могут автоматически применяться
к такому же товару другого тенанта; отклонённые и спорные связи граф не обучают.

## Товары без бренда

Пустой бренд из 1С или файла допустим и не блокирует поиск, применяемость или генерацию
описания. Система хранит статус разрешения бренда: `unknown`, `source`, `catalog`,
`manual` или `ambiguous`, а также источник, confidence и признак ручной проверки.

Надёжный каталог может дозаполнить пустые `brand` и `brand_ref`. Если каталог расходится
с непустым брендом источника, значение источника не перезаписывается: товар получает
статус `ambiguous` и требует проверки. Ручной бренд имеет приоритет.

Марка автомобиля и производитель OEM/Cross-кода не используются как бренд продаваемого
аналога. Пока бренд неизвестен или конфликтен, применяемость хранится локально и доступна
AI-описанию, но товар не обучает и не потребляет глобальный граф по одному артикулу.

Итоговый `confidence` вычисляется сервером по полноте проверенных исходных данных.
Самооценка модели сохраняется отдельно как `model_confidence` и не считается доказательством.

## Offline eval

`apps.ai_agent.evals.description` содержит 50 эталонных автозапчастей и сравнивает
старые/новые результаты по длине, обязательным идентификаторам и запрещённым фразам.
Eval не вызывает платные API в тестах. Для реального A/B прогона результаты двух версий
следует собрать во внешнем задании и передать в `compare_prompt_results`.

Новая версия не должна активироваться, если её pass rate или средний score хуже текущей.
