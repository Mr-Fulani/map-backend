# Обработка изображений товаров

Модуль `apps.media_processing` отделяет бизнес-логику MAP от API конкретного сервиса.
Оригинал `ProductImage` не изменяется: каждый результат сохраняется как отдельный
`ProductImageVariant`, а активный вариант используется в API карточки и Avito-фиде.

## Как подключить провайдера

1. Создать адаптер на базе `BaseMediaProvider`.
2. Указать стабильный `provider_id` и набор `supported_operations`.
3. Реализовать `is_configured()` и `process()`. Для асинхронного API также реализовать
   `retrieve()` или проверяемый webhook.
4. Зарегистрировать класс через `register_media_provider` при загрузке приложения.
5. Хранить ключи только в переменных окружения/secret storage. В
   `MediaProviderPolicy` находятся лишь возможности, порядок, тарифные ограничения и
   стоимость в кредитах.

Адаптер получает нормализованный `MediaProviderRequest` и возвращает
`MediaProviderResult`, поэтому контроллеры, задания, пресеты и интерфейс тенанта не
зависят от формата API поставщика.

## Выбор провайдера

Порядок разрешается при запуске задания, а не при его создании:

1. явный провайдер задания (если задан);
2. предпочтения пресета;
3. предпочтения тенанта для операции;
4. активные `MediaProviderPolicy` с учётом возможностей, приоритета и тарифного slug;
5. остальные зарегистрированные адаптеры.

Это позволяет позже добавить маршрутизацию по тарифу, цене, квоте и доступности без
изменения публичного API.

## Безопасность и эксплуатация

- Генеративная замена фона и generative fill выключены для тенанта по умолчанию.
- URL результата проверяется до скачивания; локальные и private IP блокируются.
- Размер ответа ограничен 25 MB, формат повторно проверяется Pillow.
- Задания идемпотентны в пределах тенанта и исполняются в очереди
  `media_processing` воркером изображений.
- Удаление варианта удаляет только его производный объект из хранилища.

Перед включением конкретного провайдера нужны отдельные интеграционные тесты его
подписи webhook, таймаутов, повторов, квот и схемы списания кредитов.

Генеративные операции используют контролируемый шаблон `product-media-v1`. Клиент не
может передать произвольный prompt: разрешён только `background_style`, после чего
сервер формирует positive/negative prompt с требованием не изменять сам товар.

Найденное фото с корректной идентичностью, но недостаточным разрешением получает
статус `low_confidence` и оценку `ImageAssessment` с причиной
`needs_media_processing`. Это вход будущего задания улучшения, а не причина заменить
деталь генерацией. Провайдеру запрещено менять геометрию, сторону, крепления,
разъёмы и маркировки. Для короткого видео безопасным первым режимом считается только
панорамирование/масштабирование исходного подтверждённого кадра без генерации новых
ракурсов.
