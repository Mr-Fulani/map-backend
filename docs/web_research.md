# Интернет-исследование товаров

Интернет-исследование дополняет данные каталогов внешними источниками. Оно запускается
автоматически после Tachka/Rossko, если полнота данных ниже
`WEB_RESEARCH_COVERAGE_THRESHOLD`. Все полученные из открытого интернета факты требуют
ручной проверки.

## Подключение поискового сервиса

Платформенные подключения доступны только суперпользователю:

1. Откройте **AI-агент → Сервисы интернет-поиска**.
2. Создайте подключение и выберите `brave` или `tavily`.
3. Введите API-ключ, выберите роль **Основной** или **Резервный** и задайте ограничения.
4. Сохраните подключение.
5. Выполните tenant-owned рабочий запрос и проверьте его в журнале попыток.

Административный сетевой health-check отключён: такой вызов не имеет tenant-владельца
и не может безопасно расходовать платную квоту. Доступность проверяется только
tenant-запросом, прошедшим общий ledger и лимиты.

API-ключ сохраняется в `credentials_enc`, зашифрованном первичным Fernet-ключом из
ring `FIELD_ENCRYPTION_KEYS` (`FIELD_ENCRYPTION_KEY` поддерживается только как
legacy fallback). После сохранения ключ не отображается и не возвращается через
tenant API.

Если запись подключения для провайдера ещё не создана, сохраняется обратная
совместимость с серверными переменными:

- `BRAVE_SEARCH_API_KEY`;
- `TAVILY_API_KEY`.

Как только для провайдера создана запись, она становится единственным источником его
активности, приоритетов и тарифной политики. Отключённая запись отключает и legacy
fallback из окружения.

Даже env-fallback проходит через общий durable-журнал `WebSearchAttempt` и
платформенные потолки `WEB_SEARCH_GLOBAL_REQUESTS_PER_MINUTE`,
`WEB_SEARCH_GLOBAL_MONTHLY_REQUEST_LIMIT`,
`BRAVE_SEARCH_GLOBAL_MONTHLY_REQUEST_LIMIT` и
`TAVILY_SEARCH_GLOBAL_MONTHLY_REQUEST_LIMIT`. Попытка резервируется в PostgreSQL
до сетевого вызова, поэтому параллельные worker не могут превысить месячный лимит.
Тот же журнал учитывает текстовые и image-запросы Euroauto из ProductParse, а
также каждый фактический HTTP-запрос Brave/Tavily в основном image-search
pipeline. Для image search используется стабильный business-domain товара, а не
API idempotency key/task UUID: неизвестный исход одного запуска блокирует новые
ключи и fallback на другого платного провайдера до явной сверки операции.

`WebSearchAttempt` принадлежит durable `WebSearchWorkflow`. Workflow фиксирует
неизменяемый нормализованный план (товар, запросы, порядок провайдеров и логические
слоты вызовов). Один и тот же `workflow_key` с изменённым планом отклоняется, а
другой workflow того же business-domain блокируется, пока первый не применён или
не сверен. API-ключи в план не попадают: они разрешаются непосредственно перед
новым сетевым вызовом.

Успешный или пустой ответ сначала нормализуется, ограничивается по размеру и
сохраняется в зашифрованном checkpoint. Workflow остаётся `apply_pending`, пока
caller в одной транзакции не сохранит доменный результат и не подтвердит точный
набор использованных attempt ID. Потеря worker после HTTP-ответа поэтому безопасно
переигрывает checkpoint без повторного запроса к провайдеру. Если worker потерян
до checkpoint, `STARTED` остаётся заблокированным и автоматический сетевой повтор
запрещён. После появления checkpoint задача `run_web_research` является
replay-safe и может быть восстановлена по истёкшей durable lease.

Ошибка чтения `WebSearchConnection` никогда не трактуется как отсутствие записи:
image search завершается до сети. Env key разрешён только после успешного запроса
к PostgreSQL, доказавшего, что managed connection для провайдера отсутствует.

## Маршрутизация

В админке одному подключению назначается роль **Основной**, остальным — **Резервный**.
Основной вызывается первым. При назначении нового основного предыдущий автоматически
становится резервным. В базе роли сохраняются как приоритеты `10` и `20`, после чего
маршрутизатор исключает:

- отключённые подключения;
- провайдеры без установленного адаптера;
- подключения, недоступные тарифу тенанта;
- подключения, исчерпавшие минутный или месячный лимит.

Fallback разрешён только после доказанного отказа до отправки либо документированного
ответа, означающего непринятие запроса. Timeout после отправки, HTTP 429/5xx и
невалидный ответ считаются неопределённым исходом: fallback и новый intent для того
же business-domain блокируются. Пустая валидная выдача может перейти к следующему
подключению. Каждое обращение сохраняется как `WebSearchAttempt` с провайдером,
запросом, статусом, длительностью и безопасным текстом ошибки.

Оператор снимает блокировку только явной командой, где подтверждение должно точно
совпасть с ID попытки:

```bash
python manage.py reconcile_web_search_outcome \
  --attempt-id 123 --confirm 123 \
  --action not_accepted \
  --note "Проверено в кабинете провайдера"
```

Повтор того же решения идемпотентен, конфликтующее решение отклоняется. Pending
evidence не удаляется retention-задачей и защищено от прямого удаления. Свежий
`STARTED` нельзя сверить вручную, пока исходный HTTP-вызов может выполняться;
успешный `apply_pending` checkpoint должен быть применён caller-ом и также не
может быть снят оператором. Команда ротации Fernet-ключей блокирует строки перед
перешифровкой, включая checkpoint платного поиска, чтобы не затереть параллельное
обновление.

Если локальное применение checkpoint несколько раз упало и durable dispatch
исчерпал попытки, оператор возобновляет ровно этот run без новой сети:

```bash
python manage.py resume_web_research_checkpoint \
  --run-id 456 --confirm 456
```

Команда разрешена для `apply_pending` с сохранённым успешным/пустым checkpoint,
а также для уже `applied` поискового результата, если evidence записано, но
последующая локальная запись цен/AI/final status не завершилась. Она не делает
сетевой поиск повторно, требует отсутствие неизвестных search/AI outcomes и не
заменяет сверку `STARTED`/`OUTCOME_UNCERTAIN`.

## Параметры

Безопасные настройки можно передать через JSON-поле `parameters`.

Brave:

```json
{
  "country": "ru",
  "search_lang": "ru",
  "extra_snippets": true,
  "timeout": 15
}
```

Tavily:

```json
{
  "search_depth": "basic",
  "include_raw_content": true,
  "include_domains": [],
  "exclude_domains": [],
  "timeout": 20
}
```

Пустой `allowed_plan_slugs` разрешает подключение всем тарифам. Тарифные правила можно
включать постепенно без изменения адаптеров и бизнес-логики исследования.

## Пользовательский сценарий

В карточке товара основной сценарий — **Обогатить и сгенерировать**. Отдельного
первичного запуска интернет-поиска нет. После завершённого, неудачного или пустого
исследования в его блоке появляется **Повторить интернет-поиск**.

Раздел tenant dashboard **Интернет-поиск** показывает общий журнал и доступные сервисы.
Тенант не видит ключи и не выбирает платформенное подключение напрямую: по умолчанию
используется безопасный автоматический режим.

## Поиск фотографий

Те же подключения и роли управляют поиском изображений. Brave использует отдельный
Image Search API, Tavily — выдачу `include_images` и служит резервом. Оба проходят
через единый `WebSearchAttempt`: общий RPM/месячный потолок, лимит подключения и
cross-provider reconciliation fence применяются атомарно до HTTP-вызова. На резервный
источник конвейер переходит только после доказанного безопасного исхода основного.

Запросы строятся в следующем порядке:

1. сохранённые OEM/Cross-коды из обогащения;
2. подтверждённая применяемость (марка, модель, поколение);
3. достоверный артикул и бренд;
4. название и категория как fallback.

Внутренние SKU с префиксом `OEM` и общие бренды `OEM`, `O.E.M.`, `No name`,
`Aftermarket` не считаются доказательством идентичности товара.

Проверка идентичности отделена от технического качества. Изображение человека,
логотипа, схемы, другой стороны детали или недостаточно связанного товара отклоняется
до скачивания. Подходящее фото малого разрешения сохраняется для ручной проверки со
статусом `low_confidence` и причиной `needs_media_processing`: позднее его можно
передать независимому провайдеру улучшения/апскейла. Поисковые фото никогда не
публикуются автоматически.

Результат задачи содержит реальные счётчики: сколько кандидатов нашли сервисы,
сколько прошло проверку товара, сколько было отклонено и сколько не удалось скачать.
Tenant dashboard показывает эти данные вместо общего сообщения об ограничении API.
