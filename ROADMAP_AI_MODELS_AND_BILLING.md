# Roadmap: AI-модели, тарификация и маржинальность

**Актуально на:** 2026-07-29
**Область:** выбор AI-моделей, маршрутизация задач, AI-кредиты, подписки и платежи
**Главное правило:** этап или задача получает статус `✅`, только когда выполнены критерии приёмки и успешно пройдены указанные тесты.

## Статусы

- `✅ Проверено` — реализация закончена, тесты и проверки пройдены.
- `🟡 В работе` — текущий приоритет; завершение ещё не подтверждено.
- `⬜ Запланировано` — работа не начиналась.
- `⛔ Заблокировано` — требуется решение владельца продукта или внешний доступ.

## Как обновляется прогресс

Для каждой завершённой задачи в журнал прогресса добавляются:

1. дата;
2. идентификатор задачи;
3. выполненные проверки;
4. количество успешно пройденных тестов;
5. ссылка на коммит или перечень изменённых файлов;
6. известные ограничения, если они остались.

Если хотя бы один обязательный тест не прошёл, задача остаётся `🟡`, даже если код уже написан.

## Общий test gate

Перед переводом этапа в `✅` обязательны:

- целевые unit- и integration-тесты нового поведения;
- `python manage.py check`;
- `python manage.py makemigrations --check --dry-run`;
- полный `pytest -q`;
- `npm run lint` и `npm run build`, если менялся frontend;
- безопасная интеграционная проверка провайдера или платежного sandbox, если менялась внешняя интеграция;
- проверка идемпотентности для платежей, начислений и фоновых задач;
- проверка tenant isolation и ролей доступа;
- описание отката для миграций и финансовых изменений.

## R1. Финансовая безопасность подписок — `🟡 Следующий этап`

**Цель:** исключить недополучение выручки и неограниченную AI-себестоимость.

### R1.1 Исправить годовую стоимость — `✅ Проверено`

- [x] Определить `price_yearly` как полную сумму списания за 12 месяцев.
- [x] Пересчитать текущие значения:
  - Starter: `47 040 ₽`;
  - Business: `143 040 ₽`;
  - Pro: `335 040 ₽`;
  - Enterprise: `767 040 ₽`;
  - значения основаны на скидке 20% от 12 месячных платежей.
- [x] Добавить data migration для существующих планов.
- [x] В UI отдельно показывать месячный эквивалент и полную годовую сумму.
- [x] Проверять сумму и валюту webhook против Invoice.

**Test gate:**

- monthly checkout списывает `price_monthly`;
- yearly checkout списывает полную `price_yearly`;
- период годовой подписки равен одному году;
- webhook с другой суммой не активирует подписку;
- повторный webhook не продлевает подписку второй раз.

### R1.2 Исправить выдачу кредитов годовым подпискам — `✅ Проверено`

- [x] Использовать отдельный idempotency key для каждого месяца.
- [x] Купленные кредиты сохраняются при ежемесячном обновлении.
- [x] Не обнулять активные резервы фоновых запросов.

**Test gate:**

- 12 уникальных ежемесячных начислений за год;
- повторный запуск задачи в одном месяце ничего не начисляет;

## R2. Прозрачная unit-экономика и динамическая маржа — `⬜`

**Цель:** видеть реальную себестоимость и маржу каждого AI-запроса, пакета и Тенанта.

### R2.1 Версионированные цены провайдеров

- [ ] Создать таблицу цен провайдера с `effective_from`.
- [ ] Хранить отдельно input, cached read, cached write и output.
- [ ] Поддержать USD и другие валюты провайдеров.
- [ ] Не изменять старые записи задним числом.

### R2.2 Pricing Policy

- [ ] Настраиваемый безопасный курс USD/RUB.
- [ ] Валютный buffer.
- [ ] Комиссия платежной системы.
- [ ] Налоговая нагрузка.
- [ ] Переменная инфраструктурная себестоимость.
- [ ] Целевая маржа и минимально допустимая маржа.
- [ ] Отдельная политика для подписки, маленького, среднего и большого пакета.

Базовая формула:

```text
provider_cost_rub =
  provider_cost_usd × safe_fx_rate × (1 + fx_buffer)

sale_price =
  (provider_cost_rub + variable_infra_cost)
  / (1 - payment_fee - tax_rate - target_margin)
```

### R2.3 Финансовый snapshot каждого запроса

- [ ] Записывать provider cost в USD.
- [ ] Записывать использованный курс и версию pricing policy.
- [ ] Записывать себестоимость в рублях.
- [ ] Записывать списанные кредиты и их продажную стоимость.
- [ ] Рассчитывать contribution profit и margin.
- [ ] Сохранять данные неизменяемо для последующего аудита.

### R2.4 Симулятор цен

- [ ] Экран в Django Admin или dashboard.
- [ ] Сценарии курса USD/RUB.
- [ ] Сценарии среднего числа input/output tokens.
- [ ] Сравнение моделей и пакетов.
- [ ] Предупреждение, если маржа падает ниже установленного порога.

**Test gate R2:**

- golden tests на формулы;
- Decimal без float;
- граничные курсы и комиссии;
- price snapshot не меняется при обновлении прайса;
- ни один активный пакет не проходит публикацию ниже margin floor;
- reconciliation сходится с тестовым счётом провайдера.
